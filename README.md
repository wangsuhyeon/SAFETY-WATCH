# Beach Watch — AI 수변 안전 감시 시스템

> 해수욕장·강·호수·수영장, 그리고 드론 영상에서 **물놀이 제한 구역에 사람이 들어오는 순간**을
> 브라우저가 실시간으로 찾아내, 경보음을 울리고 담당자에게 알림을 보내는 시스템입니다.
> 영상은 기기 밖으로 나가지 않고, 카메라는 최대 5대까지 동시에 감시합니다.
> **한 번 준비해 두면 인터넷 없이도 동작합니다.**

**English summary** — Beach Watch spots people entering a no-swim zone across up to five camera
feeds — beaches, rivers, lakes, pools, and aerial drone streams — entirely inside the browser
(video never leaves the device). Alerts escalate WATCH → ALERT → URGENT with a siren, an on-screen
popup, browser notifications, and automatic delivery to registered staff. Works offline once prepared, speaks alerts aloud, keeps a picture of each alert moment,
and ships a dependency-free relay server for real SMS/e-mail. Built with TensorFlow.js
and COCO-SSD, MIT licensed, Korean and English UI.

## 1. 이 프로젝트가 푸는 문제

최근 5년(2021–2025) 국내 물놀이 사망자는 **104명**입니다. 그중 해수욕장 24명·바닷가 20명으로
**바다에서만 42%**가 일어났고, 하천·계곡을 합치면 대부분이 됩니다.<sup>[1]</sup>
사망 원인의 71%는 수영 미숙(40%)과 안전 부주의(31%) — 다시 말해
**"위험한 곳에 들어가는 순간을 일찍 발견했다면 막을 수 있었던"** 사고입니다.<sup>[1]</sup>

그런데 사람의 눈에는 한계가 있습니다. 훈련된 안전요원조차 한 구역을 다시 보기까지
평균 **19.2–24.4초**가 걸리고, 물에 빠진 사람을 30초 안에 발견하는 비율은 **78%**입니다.<sup>[3]</sup>
2025년 254개 해수욕장에 **4,412만 명**이 다녀갔습니다.<sup>[2]</sup>

Beach Watch는 안전요원을 대신하지 않습니다.
**사람이 잠깐 눈을 뗀 사이의 공백을 메우는 것**이 목표입니다.

## 2. 빠른 시작

### Windows — 더블클릭

폴더 안의 **`실행.bat`** 를 더블클릭하세요. 로컬 서버가 뜨고 브라우저가 자동으로 열립니다.
Python → Node.js → PowerShell 순으로 있는 것을 찾아 쓰므로 **아무것도 설치돼 있지 않아도 동작합니다**
(PowerShell은 Windows 기본 탑재).

### macOS / Linux

```bash
./run.sh          # 기본 포트 8000
./run.sh 8080     # 포트 지정
```

### 직접 실행

```bash
python3 -m http.server 8000 --bind 127.0.0.1
#   또는
node serve.js 8000
```

접속 주소: <http://127.0.0.1:8000/index.html>

> **`index.html`을 그냥 더블클릭하면 카메라가 동작하지 않습니다.**
> 브라우저가 `file://`을 안전한 주소로 보지 않아 카메라 사용을 막기 때문입니다.
> 반드시 `localhost` / `127.0.0.1` 또는 https로 접속하세요.
> (카메라 없이 동작만 볼 때는 `file://`에서도 **체험 모드**가 작동합니다.)

### 온라인에 올려서 쓰기 (휴대폰에서도 열립니다)

`https` 로 올리면 카메라가 바로 동작하고, 현장에서 휴대폰으로 열 수 있습니다.
**Netlify Drop 에 이 폴더를 끌어다 놓으면 30초면 끝납니다.**
방법과 배포 뒤 확인 사항은 **[DEPLOY.md](DEPLOY.md)** 에 정리했습니다.

빌드 도구도, 서버 프로그램도, 데이터베이스도 필요 없습니다. `index.html` 하나가 전부입니다.

## 4. 위험 구역 그리기 — 손으로 그리듯

실제 파도선과 물놀이 제한 구역은 직선이 아닙니다.
그래서 경계는 두 점을 잇는 직선이 아니라, **화면 위에 손으로 그리는 자유 곡선**입니다.

### 그리는 방법

| 동작 | 결과 |
|---|---|
| **화면을 끈다 (드래그 / 손가락으로 쓸기)** | **손으로 그리듯 곡선이 그려집니다.** 지금 그리는 모양이 실시간으로 보입니다 |
| 한 번 누른다 (클릭 / 탭) | 점이 하나 추가됩니다. 알아서 알맞은 자리에 끼워져 선이 꼬이지 않습니다 |
| 점을 끈다 | 그 점만 옮겨집니다 |
| 점을 두 번 누른다 | 그 점이 지워집니다 |

끌어서 그린 궤적은 곧바로 자동으로 다듬어집니다. 손떨림으로 생긴 점은 걸러지고
곡선 모양은 그대로 유지되므로, 40번 넘게 흔들며 그려도 점 10개 안팎으로 정리됩니다.
화면에는 각진 꺾은선이 아니라 **부드러운 곡선**으로 그려집니다.

### 두 가지 방식

| 방식 | 위험 판정 | 언제 쓰나 |
|---|---|---|
| **선 긋기** | 선 **바깥쪽(물 쪽)** 에 사람이 있으면 위험 | 굽은 파도선, 완만한 수심 경계 |
| **영역 칠하기** | 칠한 **영역 안**에 사람이 들어오면 위험 | 이안류 구역, 암초, 배수구처럼 국소적인 위험 지대 |

- 두 방식을 오가도 모양이 이어집니다. 선을 영역으로 바꾸면 위험한 쪽을 덮는 영역이 자동으로
  만들어지고, 되돌리면 원래 선으로 돌아옵니다.
- **ㄷ자처럼 안으로 파인 모양**도 정확히 판정합니다. 파인 부분은 안전으로 처리됩니다.
### 버튼 다섯 개가 각각 하는 일

화면에서도 **버튼 위에 마우스를 올리면 아래에 한 줄 설명이 뜹니다.**

| 버튼 | 무엇을 하나 | 언제 쓰나 |
|---|---|---|
| **그리기 시작** | 화면 위에 직접 그릴 수 있게 함 | 처음 구역을 잡을 때. 그리는 동안에도 감시는 계속됩니다 |
| **한 점 되돌리기** | **방금 찍은 점 하나만** 없앰 | 잘못 눌러 점이 하나 더 생겼을 때. 여러 번 누르면 하나씩 거슬러 올라갑니다 |
| **선 다듬기** | **모양은 그대로 두고 점 개수만** 줄임 | 손으로 그려 점이 수십 개가 됐을 때. 한 번 눌러 정리한 뒤 손보면 훨씬 쉽습니다 |
| **처음 모양으로** | 이 장소의 기본 경계선으로 되돌림 | 처음부터 다시 그릴 때 (그린 것이 전부 사라집니다) |
| **다른 카메라에도 똑같이** | 지금 구역을 나머지 카메라에 복사 | 같은 해안선을 여러 대가 나눠 볼 때 |

#### 한 점 되돌리기 vs 선 다듬기 — 헷갈리기 쉬운 둘

둘 다 점을 줄이지만 **목적이 정반대**입니다.

- **한 점 되돌리기**는 *실수를 취소*하는 것입니다. 마지막 점 하나만 사라지고
  나머지는 손대지 않습니다. 탭이 빗나가 엉뚱한 곳에 점이 생겼을 때 바로 누르세요.
- **선 다듬기**는 *모양을 유지한 채 정리*하는 것입니다. 어느 점이 사라질지는
  시스템이 정합니다 — 곡선의 생김새를 바꾸지 않는 점만 골라 없앱니다.
  손으로 쓱 그으면 점이 40개 넘게 생기는데, 그러면 손잡이가 촘촘히 붙어 하나를
  집어 옮기기가 어렵습니다. **그릴 때는 마음껏 긋고, 다듬은 뒤에 손보세요.**

> 선 다듬기는 [Douglas–Peucker](https://en.wikipedia.org/wiki/Ramer%E2%80%93Douglas%E2%80%93Peucker_algorithm)
> 방식입니다. 원래 선에서 가장 멀리 벗어난 점만 남기고, 허용 오차 안에 들어오는 점은
> 지웁니다. 그래서 **점은 줄어도 파도선의 굴곡은 그대로 남습니다.**
> 이미 충분히 단순하면 "줄일 점이 없습니다"라고 알려 주고 아무것도 바꾸지 않습니다.
### 높이 · 360° 회전

그리기 카드 아래의 슬라이더 두 개로 그린 모양을 **통째로** 옮기고 돌릴 수 있습니다.

| 슬라이더 | 하는 일 |
|---|---|
| **높이** | 모양은 그대로 둔 채 위아래로 옮깁니다 |
| **회전** | **0°부터 360°까지 자유롭게 돌립니다** |

- 카메라를 비스듬히 달면 파도선이 화면에서 기울어 보입니다. 90°로 돌리면 세로 경계선이
  되고, 그 사이 어떤 각도든 만들 수 있습니다.
- **선이든 손으로 그린 곡선이든 영역이든 똑같이 돌아갑니다.**
- 각도는 절대값입니다. 슬라이더를 0°로 되돌리면 원래 모양 그대로 돌아옵니다.
- 화면을 벗어나면 **각도는 유지한 채** 안쪽으로 줄여 넣습니다. 모양이 찌그러지지 않습니다.
- 화면 비율(16:9)을 고려해 돌리므로, 45°로 맞추면 화면에서도 실제로 45°입니다.
- 그린 구역은 **카메라별·장소별로 저장**되어 다음 접속에도 그대로 유지됩니다.
- 그리기를 시작하면 화면 아래에 조작 안내가 뜹니다. **화면을 가리면 안내문의 `✕` 를 눌러
  닫으세요.** 한 번 닫으면 다음부터 뜨지 않고, 같은 설명은 그리기 카드 안에 그대로 남습니다
  (다시 보고 싶으면 카드의 `화면 위 안내 다시 보기`).

## 5. 위험 상황 알림

물놀이 제한 구역에 사람이 들어오면 시스템이 곧바로 알립니다.
다만 **한 번 스친 것만으로 사이렌을 울리지는 않습니다.**

### 몇 명인지 세는 방법

**화면에 그려진 네모박스 하나가 사람 한 명입니다.** 위험 구역 안에 박스가 2개 있으면
"2명 있습니다"라고 알립니다. 바다에서는 멀리 있는 사람들이 각각 작은 박스로 잡히므로,
이 대응이 어긋나면 화면과 알림이 서로 다른 말을 하게 됩니다.

- **사람이 늘어나면 바로 다시 알립니다.** 1명일 때 알림을 보낸 뒤 2명이 되면,
  등급이 그대로여도 "2명"으로 새로 보냅니다. 줄어들 때는 보내지 않습니다(경보 피로 방지).
- 한 사람이 여러 번 잡혀 여러 명으로 세어지던 문제는 v3에서 고쳤고
  회귀 테스트로 고정돼 있습니다 (19장).
- **떨어져 있는 여러 사람은 절대 하나로 합치지 않습니다.** 서로 조금도 겹치지 않는
  두 박스는 아무리 가까워도 합치지 않습니다 — 바다에는 나란히 떠 있는 사람이 많기 때문입니다.
- 성수기처럼 화면에 사람이 많아도 **한 번에 최대 100명**까지 찾습니다. 상한이 낮으면
  멀리 있는 사람부터 잘려 나가 인원이 적게 세어집니다.

> 검증: 나란히 떠 있는 **20명이 20명 그대로** 남고, 같은 사람이 5곳에서 잡힌 6명은
> **정확히 6명**으로 합쳐지는 것을 자가 진단으로 고정해 두었습니다.

### 3단계로 올라가는 경보

| 단계 | 언제 | 무슨 일이 일어나나 |
|---|---|---|
| **주의** | 구역에 들어온 직후 | 화면에 노란 표시만. 소리 없음 (파도인지 사람인지 확인하는 중) |
| **경고** | 1.5초 이상 계속 있으면 | 경보음 한 번 + 화면 팝업 + 브라우저 알림 + 담당자에게 자동 전송 |
| **긴급** | 정한 시간(기본 6초, 강은 4초)을 넘기면 | 사이렌 반복 + 화면 테두리 경광등 + 담당자에게 다시 전송 |

단발성 오탐이 곧바로 사이렌이 되면 아무도 경보를 믿지 않게 됩니다.
3단계 구조는 정확도 지표가 아니라 **이 신뢰 문제**를 풀기 위한 장치입니다.

### 알림이 가는 길

| 경로 | 자동 여부 | 설명 |
|---|---|---|
| 화면 팝업 · 경보음 | 자동 | 관제 화면을 보고 있을 때 |
| **음성 안내** | 자동 | 화면을 안 보고 있어도 어느 카메라에서 얼마나 급한지 들립니다 |
| **브라우저 알림** | 자동 | **🔔 알림 켜기** 를 한 번 누르면, 다른 창을 보고 있어도 화면에 뜹니다 |
| **알림 서버 전송** | 자동 | 담당자에게 등록한 서버 주소로 위험 상황이 자동 전달됩니다 |
| 전화 · 문자 · 메일 | 사람이 누름 | 경보 창에 뜨는 원터치 버튼 |

> **솔직한 한계** — 브라우저만으로는 문자·이메일을 **자동으로** 보낼 수 없습니다.
> 자동 전송이 되는 경로는 **알림 서버 주소** 하나뿐이며, 받는 서버에서 외부 접속을
> 허용해야 합니다. 허용되지 않으면 시스템이 조용히 넘어가지 않고 **실패 이유를 화면에 남깁니다.**
> 휴대폰·이메일을 적어 두면 경보 창에 전화·문자·메일 버튼이 생겨 한 번에 연결할 수 있습니다.

### 담당자 등록

**＋ 담당자 등록** 으로 이름·역할·휴대폰·이메일·알림 서버 주소를 넣습니다 (최대 12명).

- **근무 중인 사람에게만** 갑니다. 교대하면 대기로 바꿔 두면 됩니다
- 사람마다 **언제부터 받을지**를 `경고부터` / `긴급만` 중에서 고릅니다
- 같은 사람에게 15초 안에 반복해서 보내지 않되, **경고 → 긴급으로 올라가면 반드시 보냅니다.**
  상황이 나빠진 사실이 중복 방지 때문에 묻히면 안 되기 때문입니다
- 상황이 끝나면 기억이 초기화되어, 다음 사건의 첫 경고가 막히지 않습니다
- **시험 발송** 버튼으로 연결이 되는지 미리 확인할 수 있습니다

알림 서버로 보내는 내용:

```json
{
  "type": "beach-watch-alert",
  "test": false,
  "level": "critical",
  "site": "beach",
  "camera": "북측 1구역",
  "zoneMode": "polygon",
  "peopleInZone": 1,
  "dwellSeconds": 7,
  "recipient": { "name": "김안전", "role": "안전요원 · 1구역" },
  "message": "[긴급] 위험 구역에 사람 1명이 있습니다.",
  "timestamp": "2026-08-21T04:27:52.104Z"
}
```

## 6. 카메라 최대 5대

카메라 수에 따라 화면이 자동으로 나뉘고, **경보가 난 카메라는 스스로 크게 확대**됩니다.
관제요원이 어느 화면에서 일이 났는지 찾아 헤매지 않게 하기 위한 동작입니다.

- 카메라마다 **위험 구역·추적 상태·경보 단계·밝기 판단이 완전히 따로** 돌아갑니다.
  한 대에서 난 헛경보가 다른 대의 경보를 오염시키지 않습니다.
- AI 감지 기능은 **한 번만 불러와 함께 씁니다.** 그래서 메모리는 카메라 수와 무관합니다.
  대신 카메라를 번갈아 살피므로 **한 바퀴 도는 시간**이 대수에 비례해 늘어나며,
  그 값을 시스템 상태 패널에 그대로 보여 줍니다. 5대여도 사람의 스캔 주기(약 20초)보다 훨씬 짧습니다.
- 오른쪽 안전 상태에는 **가장 위험한 카메라**가 대표로 뜨고, 사람 수는 전체 합계입니다.

## 7. 설치 장소별 설정

| 유형 | 긴급 알림까지 | 최소 인체 크기 | 특징 |
|---|---|---|---|
| 해수욕장 | 6초 | 5×7px | 파도를 사람으로 잘못 보는 것을 막는 데 집중 |
| 강 · 계곡 | **4초** | 5×6px | 급류는 몇 초 만에 떠내려 보내므로 가장 빠르게 |
| 호수 · 저수지 | 7초 | 5×6px | 잔잔해 헛경보가 적으니 민감도를 낮춰 멀리까지 |
| 수영장 | 5초 | 10×12px | 크고 붐비므로 다시 확인 횟수를 늘려 안정화 |
| 드론 항공 | 5초 | **3×3px** | 하늘에서 보면 사람이 아주 작음 + 움직임 감지 |

밝기 상황(낮·맑음 / 흐림·안개 / 밤·어두움 / 햇빛 반사)은 매 0.5초 화면을 살펴
**스스로 판단**하며, 원하면 직접 고를 수도 있습니다.
밤으로 판단하면 "일반 카메라로는 멀리 있는 사람을 찾기 어렵다"고 화면에 경고합니다.
성능이 떨어진 사실을 숨기지 않기 위해서입니다.

## 8. 드론 · CCTV 연결

브라우저는 CCTV·드론이 흔히 쓰는 형식(RTSP)을 바로 열지 못합니다. 두 가지 길이 있습니다.

1. **가상 카메라로 넘기기 (가장 쉬움)** — 드론 앱 화면을 OBS 같은 프로그램으로 받아
   가상 카메라로 내보내면, **＋ 카메라 추가 → 이 기기 카메라** 목록에 그대로 나타납니다.
2. **인터넷 카메라 주소** — 영상을 `HLS(.m3u8)` · `일반 영상(MP4/WebM)` · `MJPEG` 중 하나로
   바꿔 주는 중계 주소를 넣습니다. HLS는 브라우저가 못 읽으면 재생기를 자동으로 내려받습니다.

   > 중계 서버에서 **외부 접속 허용(CORS)** 이 필요합니다. 허용되지 않으면 영상은 보이지만
   > 화면 밝기 자동 판단이 꺼집니다(감지는 계속 동작). https 페이지에서는 http 주소를 못 불러오며,
   > 시스템이 미리 알려 줍니다.

**드론은 기체가 움직입니다.** 화면 기준으로 그린 구역은 화면이 바뀌는 순간 의미가 없어지므로,
드론 유형을 고르면 시스템이 매 0.5초 화면을 비교해 **움직이는 동안 구역 판정을 자동으로 멈추고**
`카메라 움직임 · 구역 판정 잠시 멈춤` 을 띄웁니다. 안정되면 스스로 다시 시작합니다.

## 9. AI가 하는 일과 하지 않는 일

| 구성요소 | 종류 |
|---|---|
| **사람 찾기 (COCO-SSD / MobileNet v2, TensorFlow.js)** | **학습된 인공지능** |
| 밝기 판단, 겹친 것 합치기, 프레임 간 따라가기, 구역 판정, 경보 단계, 움직임 감지 | 일반 계산 로직 (단위 테스트로 고정) |

인공지능은 **"이 화면 조각이 사람인가"** 하나만 판단하고, 나머지는 전부 검증 가능한
일반 코드로 처리했습니다. 인명 안전 시스템에서 **왜 그렇게 판단했는지 설명할 수 없는 부분**을
최소로 줄이기 위한 선택입니다.

먼 바다의 사람은 화면 축소 과정에서 사라지기 때문에, 화면 전체를 한 번 보고
**3×2로 나눠 확대한 칸을 여섯 번 더** 봅니다(프레임당 7번). 그렇게 찾은 것들을 한 사람으로
합치고, 여러 프레임에 걸쳐 계속 보이는 대상만 사람으로 확정합니다.

모델 구조·학습 데이터·연산 특성·오류 유형·대안 비교·개선 계획은
**[AI_STACK.md](AI_STACK.md)** 에 상세히 정리했습니다.

## 10. 인터넷 없이 쓰기

해변·강가·저수지에는 안정적인 인터넷이 없는 곳이 많습니다. 그런데 AI 감지 기능은 처음
한 번 인터넷에서 받아야 합니다. **인터넷이 끊기면 감시가 아예 시작되지 않는 구조**였습니다.

그래서 **한 번 받은 것을 브라우저 안에 저장해 두고, 다음부터는 인터넷 없이 씁니다.**

| 단계 | 조작 |
|---|---|
| 1 | 인터넷이 되는 곳에서 오른쪽 **운영 설정 → 인터넷 없이 쓸 수 있게 준비** 를 누릅니다 |
| 2 | 위쪽 **오프라인** 배지가 `준비 완료`로 바뀝니다 |
| 3 | 이후에는 인터넷이 끊겨도 카메라를 연결하면 그대로 감지가 시작됩니다 |

- 저장되는 것은 **AI 라이브러리와 모델 가중치**뿐입니다. 영상은 어떤 경우에도 저장되지 않습니다.
- 저장된 것을 쓰면 진단 기록에 `저장해 둔 것에서 불러왔습니다 (인터넷 불필요)` 가 남습니다.
- 별도 설치 프로그램이나 서비스 워커 파일이 필요 없습니다. `index.html` 하나 그대로입니다.

> 실측: 인터넷을 완전히 차단한 브라우저에서 저장해 둔 TensorFlow.js 4.22.0 을 불러와
> 연산 엔진 초기화까지 성공하는 것을 자동 테스트로 확인했습니다.

## 11. 관제실에서 쓰기 — 음성 · 관제 모드 · 단축키

### 음성 안내

경보가 뜨면 **말로도 읽어 줍니다.**

> "긴급. 북측 1구역, 위험 구역에 1명. 7초째입니다."

관제요원이 화면을 보고 있지 않아도, 다른 일을 하고 있어도 **어느 카메라에서 얼마나 급한
상황인지** 바로 알 수 있습니다. 경보음만으로는 전달되지 않는 정보입니다.
언어 설정을 따라 한국어·영어로 읽으며, 브라우저 내장 기능이라 추가 비용이 없습니다.
같은 상황을 반복해 읽지 않되, **등급이 올라가면 즉시 다시 읽습니다.**

### 관제 모드

**F** 키 또는 위쪽 `관제 모드` 버튼을 누르면 설명 카드와 사이드바가 사라지고
**카메라가 화면을 가득 채웁니다.** 실제 관제실 화면에 띄우기 위한 모드입니다.
`Esc` 로 빠져나옵니다.

### 키보드 단축키

| 키 | 하는 일 |
|---|---|
| `1`–`5` | 그 번호의 카메라를 크게 보기 |
| `E` | 위험 구역 그리기 시작 / 끝내기 |
| `F` | 관제 모드 |
| `D` | 체험 모드 시작 / 끄기 |
| `M` | 경보음 켜기 / 끄기 |
| `T` | 스스로 점검하기 |
| `Tab` | (그리는 중) 다음 점 선택 |
| `← ↑ ↓ →` | (그리는 중) 선택한 점 옮기기 · `Shift` 를 누르면 크게 |
| `?` | 단축키 도움말 |

**화살표 키로 구역을 그릴 수 있다는 점이 중요합니다.** 마우스를 쓰기 어려운 환경(장갑,
트랙패드 없는 관제 PC)과 스크린리더 사용자를 위한 것으로, 점을 옮길 때마다 위치를
소리로도 알려 줍니다. 입력 칸에 글자를 쓰는 동안에는 단축키가 동작하지 않습니다.

## 12. 경보 순간의 화면

"그때 진짜 사람이었나, 파도였나" — 지나간 경보를 확인할 방법이 없었습니다.
이제 **경보가 뜬 순간의 화면을 캡처해 경보 기록에 붙입니다.** 눌러서 크게 볼 수 있고,
필요하면 이미지로 내려받을 수 있습니다.

> **이 이미지는 기기 밖으로 나가지 않습니다.** 메모리에만 있고 저장되지 않으며,
> 새로고침하면 사라집니다. 알림 서버로도 전송되지 않습니다 — 전송 본문은 여전히
> 텍스트뿐입니다. 원치 않으면 **운영 설정** 에서 끌 수 있습니다.

오탐이 왜 났는지 눈으로 확인할 수 있어야 감지 설정을 제대로 조절할 수 있습니다.

## 13. 감시 시간대

야간에는 오탐이 늘어납니다. 그런데 해수욕장은 개장 시간이 정해져 있습니다.
**운영 설정 → 감시 시간대만 경보** 를 켜고 시간을 정하면, 그 시간에만 경보를 울립니다.

- 시간대 **밖**에서도 감지와 화면 표시는 계속됩니다 — **소리와 알림 전송만** 멈춥니다.
- 기록은 그대로 남으므로 나중에 확인할 수 있습니다.
- `22:00–06:00` 처럼 자정을 넘기는 구간도 됩니다 (야간 전용 감시).

밤새 울리는 헛경보에 익숙해지면, 정작 필요한 경보까지 무시하게 됩니다.
이 기능은 정확도를 올리는 장치가 아니라 **경보를 믿을 수 있게 유지하는** 장치입니다.

## 15. 멈추지 않게 만드는 장치

인명 안전 시스템에서 가장 위험한 실패는 **요란하게 죽는 것이 아니라 조용히 멈추는 것**입니다.
화면은 "감시 중"인데 실제로는 아무것도 보고 있지 않은 상태 — 이 시스템은 그 상태를 만들지 않는 데
가장 많은 공을 들였습니다.

| 상황 | 예전이라면 | 지금 |
|---|---|---|
| 감지 기능(AI)을 못 받음 | 화면은 **LIVE · 감시 중**인데 아무것도 감지하지 않음 | **감시를 시작하지 않고** 실패 사유를 화면에 남김 |
| 한 CDN이 막힌 망(학교·사내) | 3번 재시도가 전부 같은 이유로 실패 | 예비 주소로 자동 전환 |
| 카메라 1대가 고장 | **5대 전부** 감시 정지 | 고장난 1대만 내리고 나머지는 계속 감시 |
| 중계 서버가 죽음 | 마지막 화면이 얼어붙은 채 계속 "정상" | 새 영상이 6초간 안 오면 **끊김으로 판정** 후 재연결 |
| 카메라 권한 거부 · 주소 오타 | 안내가 한 프레임 만에 사라짐 | 해결될 때까지 화면에 계속 표시 |
| 사람이 파도에 잠깐 가림 | 체류 시간이 0으로 초기화되어 **긴급까지 못 올라감** | 몇 프레임은 같은 사람으로 기억해 시간을 이어감 |
| 담당자에게 시험 발송 | 직후 15초간 **진짜 경보가 그 사람에게만 안 감** | 시험 발송은 중복 방지 시계를 건드리지 않음 |

이 항목들은 전부 자가 진단(139개)과 실제 브라우저 조작 시나리오로 고정해 두었습니다.

## 17. 임팩트

공개 통계에 근거한 **보수적 추정**입니다. 산출 근거와 계산식은 [IMPACT.md](IMPACT.md)에 있습니다.

| 입력 | 값 | 출처 |
|---|---|---|
| 바다 권역 연평균 사망자 | (24+20) ÷ 5 = **8.8명/년** | 행안부 2021–2025<sup>[1]</sup> |
| 조기 발견이 유효한 사고 비중 | 40% + 31% = **71%** | 수영 미숙 · 안전 부주의<sup>[1]</sup> |
| 사망 1인당 사회적 비용 | **5억 3,379만 원** | 도로교통공단 2022<sup>[4]</sup> |

기본 시나리오(전국 254개소 도입, 놓친 사고의 20% 회복, 유효 운영 시간 70%):

```
예방 가능 사망자 = 8.8 × 71% × 20% × 70% × 100% ≈ 0.87명/년
사회적 비용 절감 = 0.87 × 5.34억 ≈ 4.7억 원/년
추가 하드웨어 비용 = 0원 (기존 CCTV·웹캠 + 브라우저)
```

> 더 큰 숫자를 만들 수 있었지만, **검증 가능한 작은 숫자**를 택했습니다.
> 익수 예방 효과를 직접 측정한 국내 실증 데이터는 아직 없습니다. 위 값은 인과 효과의
> 측정치가 아니라 명시된 가정 위의 추정치이며, 실증은 다음 단계인 현장 파일럿의 목표입니다.

## 18. 알려진 한계

- **밤에는 멀리 있는 사람을 잘 못 찾습니다.** 일반 카메라의 물리적 한계이며, 시스템이 밤으로
  판단하면 화면에 경고합니다. 실전에서는 열화상 카메라를 함께 쓰는 것이 정답입니다.
- 햇빛 반사가 강한 시간대에는 헛경보가 늘어납니다. 다시 확인 횟수를 높여 완화합니다.
- 위험 구역은 화면 좌표 기준이라 **카메라를 옮기면 다시 그려야 합니다** (드론 유형은 움직임을
  감지해 자동으로 판정을 멈춥니다).
- 카메라를 늘리면 한 바퀴 도는 시간이 대수에 비례해 길어집니다. 실제 값은 시스템 상태에서 확인하세요.
- 위험 구역은 브라우저에 저장됩니다. 다른 컴퓨터·다른 브라우저에서는 다시 그려야 합니다.
- 브라우저는 RTSP를 직접 못 열어 드론·CCTV는 중계 주소나 가상 카메라가 필요합니다.
- 문자·이메일 **자동** 발송은 브라우저만으로 불가능합니다. 중계 서버가 필요하며,
  이 저장소의 `relay-example.js` 로 30초 만에 띄울 수 있습니다 ([RELAY.md](RELAY.md)).
- 오프라인 저장은 브라우저·기기 단위입니다. 다른 PC 에서는 그 PC 에서 한 번 준비해야 합니다.
- 경보 순간 스냅샷은 메모리에만 남아 **새로고침하면 사라집니다**. 보관하려면 그때 내려받으세요.
- 음성 안내는 브라우저 내장 음성을 씁니다. 기기에 한국어 음성이 없으면 읽지 못할 수 있습니다.
- **자체 정확도 수치(mAP·재현율)를 제시하지 않습니다.** 라벨링된 국내 해변 테스트셋이 없기 때문입니다.
  제시 가능한 것은 로직 단위 테스트, 처리 속도, 실측 감시 주기뿐입니다
  ([AI_STACK.md](AI_STACK.md) 6·8장에 이유와 개선 계획).
- 이 시스템은 **보조 도구이며 안전요원을 대체하지 않습니다.**

### v3에서 고친 카운트 오류

화면에 1명 있는데 `위험 구역 사람`이 4로 표시되던 문제가 있었습니다.
화면을 3×2로 나눠 보는 구조에서 **한 사람은 최대 5곳에 동시에 잡히는데**, 예전 방식은
"점수 높은 순으로 훑으며 겹치면 버린다"는 단순한 방법이라 A와 B가 겹치고 B와 C가 겹치지만
A와 C는 안 겹치는 경우 A와 C가 모두 살아남았습니다.

고친 내용: **유니온-파인드로 연결된 것들을 한 덩어리로 묶고**, 같은 구간에서 나온 중복도
아주 강하게 겹치면 합치고, 나눠 본 칸의 가장자리에서 잘린 것 대신 온전한 것을 대표로 쓰고,
겹침 폭을 16%→22%로 늘리고, 큰 사람 앞의 작은 아이는 삼키지 않도록 면적 하한을 뒀습니다.
이 시나리오들은 전부 회귀 테스트로 고정되어 있습니다.

### 협업 방식

화·금 30분 회의에서 각자 막힌 지점을 하나씩 공유하고, 해결 여부와 무관하게 기록했습니다.
4주차부터 **병합 전 스스로 점검 통과를 필수 규칙**으로 적용했고, 의사결정은 한 줄짜리

## 22. 3개 언어 지원 — 한국어 · English · 简体中文

화면의 **모든** 문구가 **세 언어**로 준비되어 있습니다 (각 언어 352개 문구).
오른쪽 위 `설정 → 언어`에서 즉시 바뀌며, 새로고침 없이 경보 문구·진단 기록·도움말·
**음성 안내**까지 함께 전환됩니다.

| 언어 | 문구 수 | 음성 안내 | 시각 표기 |
|---|---|---|---|
| 한국어 | 352 | `ko-KR` | 24시간 |
| English | 352 | `en-US` | 24-hour |
| 简体中文 | 352 | `zh-CN` | 24小时 |

중국어를 넣은 이유는 단순합니다. 2025년 해수욕장 이용객 4,412만 명<sup>[2]</sup> 중에는
외국인 관광객이 있고, 그중 중국어권 비중이 가장 큽니다.
**관제 화면을 볼 사람이 한국인만은 아닙니다.**

### 번역이 새는 것을 막는 자동 검사

번역은 빠뜨리기 쉽고, 빠뜨린 것이 그대로 화면에 나갑니다. 그래서 자가 진단이 검사합니다.

- **키 대조** — 세 언어의 문구 목록이 완전히 같은지 (누락·잉여 모두)
- **빈 문구** — 값이 비어 있는 항목이 없는지
- **번역 누락 탐지** — 영어·중국어 사전에 **한글이 남아 있으면 실패**시킵니다
- **치환 변수 대조** — `{count}`·`{name}` 같은 변수가 세 언어에서 짝이 맞는지.
  번역하다 `{count}`를 빠뜨리면 경보 문구에서 **인원 수가 사라진 채 발송**됩니다
- **선택 목록 일치** — 설정의 언어 목록이 실제 지원 언어와 같은지

선택한 언어는 브라우저에 저장되어 다음 접속에도 유지됩니다.
언어를 하나 더 늘리려면 `src/i18n/` 에 사전 파일을 하나 넣고 `SUPPORTED_LANGUAGES` 에
코드를 추가하면 됩니다. 위 검사가 전부 새 언어까지 따라갑니다.
