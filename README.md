# Beach Watch

브라우저에서 카메라 영상을 분석해 설정한 경계선 또는 위험 영역에 사람이 들어오는 상황을 감지하는 수변 안전 관제 프로토타입입니다. 감지 결과는 화면 경보와 브라우저 알림으로 표시합니다. 실제 구조·구난 판단을 대신하지 않습니다.

한국어·영어·중국어 UI를 제공하며, 카메라 입력은 최대 5개까지 구성할 수 있습니다. 영상 분석은 브라우저의 TensorFlow.js와 COCO-SSD 모델을 사용합니다. 계정 기능은 별도의 Node.js 서버와 SQLite 데이터베이스를 사용합니다.

## 문제 정의와 구조

관제자가 여러 카메라를 계속 살피기 어려운 상황에서, 설정한 위험 경계에 사람이 진입했음을 더 빨리 알아차리도록 돕는 것이 프로젝트의 범위입니다. 이 도구는 보조 경보이며 구조요원을 대체하거나 익수 여부를 판정하지 않습니다.

```text
카메라 영상 → 브라우저의 TensorFlow.js / COCO-SSD → 경계선·영역 판정 → 화면 경보
브라우저 계정 화면 → Express API → SQLite (계정·세션·이벤트)
```

## 빠른 시작

### 필요한 환경

- Node.js 22.13 이상 권장 (`node:sqlite` 필요)
- npm
- 카메라를 쓰려면 `localhost` 또는 HTTPS로 접속할 수 있는 브라우저와 카메라 권한
- 첫 모델 로드에는 인터넷 연결이 필요합니다. 모델과 라이브러리는 `index.html`에서 CDN으로 불러옵니다.

### 실행

프로젝트 폴더에서 실행합니다.

```bash
npm install
npm start
```

브라우저에서 <http://localhost:3000> 을 여세요. 서버는 같은 주소에서 웹 화면과 `/api/*` 계정 API를 제공합니다. 서버를 시작하면 `data/beachwatch.db`가 생성됩니다. 포트를 바꾸려면 `.env.example`을 참고해 `.env`에 `PORT=8080`처럼 지정하세요.

서버 상태는 <http://localhost:3000/api/health> 에서 확인할 수 있습니다.

### 운영 배포: 계정 기능 포함

`render.yaml`은 Render에서 이 저장소를 웹 서비스로 배포하기 위한 설정입니다. GitHub 저장소를 Render에 연결해 Blueprint로 배포하면 화면, Express API, SQLite가 같은 HTTPS 주소에서 동작하며 `/var/data` 영속 디스크에 데이터베이스가 저장됩니다. 배포가 완료된 서비스 주소로 접속하면 회원가입도 바로 사용할 수 있습니다.

기존 GitHub Pages·Netlify 같은 정적 홈페이지를 유지한다면 다음을 추가로 설정하세요.

1. `render.yaml`으로 API 서버를 배포하고, 서비스의 HTTPS 주소를 확인합니다.
2. API 서버 환경 변수 `APP_ORIGIN`에 정적 홈페이지의 정확한 주소를 넣습니다. 여러 주소는 쉼표로 구분합니다.
3. 정적 홈페이지의 `index.html`에서 `beach-watch-api-url` 메타 태그 `content` 값에 API 서버 주소를 넣고 다시 배포합니다.

이 구성은 CORS 허용 출처와 `SameSite=None; Secure` 세션 쿠키를 사용합니다. `APP_ORIGIN`에는 와일드카드를 쓰지 말고 실제 HTTPS 주소만 등록하세요.

## 첫 감시 설정

1. 화면의 **카메라 추가** 또는 **카메라 연결**을 눌러 기기 카메라나 지원되는 스트림 입력을 선택합니다. 카메라가 없어도 **시뮬레이션 실행**으로 화면 흐름을 살펴볼 수 있습니다.
2. 카메라 화면이 선택된 상태에서 **그리기 시작**을 누릅니다.
3. 영상 위를 눌러 경계 점을 추가합니다. 점을 끌어 위치를 바꾸고, 마지막 점 삭제나 점 줄이기로 모양을 다듬습니다. 편집을 마치면 그리기 버튼을 다시 눌러 끝냅니다.
4. **경계선**은 선의 위험 쪽(화면에서 안내하는 바깥쪽)에 들어온 사람을 감지하고, **위험 영역**은 닫힌 영역 안에 들어온 사람을 감지합니다. 현장 화면에서 방향과 위치가 맞는지 확인하세요.
5. 여러 카메라에서 같은 구역을 쓸 때 **모든 카메라에 적용**을 누릅니다. 별도 카메라별 설정은 각 카메라에서 확인하세요.

카메라 영상은 브라우저에서 분석됩니다. 브라우저 저장소에는 위험 구역과 화면 설정이 남을 수 있으므로 공용 기기에서는 설정의 데이터 삭제 기능을 사용하세요.

## 회원가입 및 서버 연결

회원가입·로그인·비밀번호 재설정은 `server.js`의 API와 SQLite가 실행 중이어야 작동합니다. GitHub Pages 같은 정적 호스팅에 파일만 올린 경우 계정 API가 없으므로 가입할 수 없습니다. `render.yaml`로 전체 앱을 배포하거나, 위의 분리 배포 설정으로 API를 연결하세요.

로컬에서 “서버 응답을 받지 못했습니다”라는 메시지가 나오면:

1. 프로젝트 폴더에서 `npm start`를 실행합니다.
2. 터미널에 `Beach Watch server → http://localhost:3000`이 표시되는지 확인합니다.
3. `http://localhost:3000/api/health`를 열어 JSON 응답을 확인하고, 페이지도 `http://localhost:3000`에서 엽니다.
4. 정적 미리보기 서버나 `file://` 주소에서 열었다면 위 주소로 다시 접속합니다.

계정 비밀번호와 보안 질문 답변은 서버에서 해시 처리해 저장되며, 브라우저에는 HttpOnly 세션 쿠키가 사용됩니다. 운영 환경에 공개하기 전에는 HTTPS, 백업, 데이터 보관 정책, 운영 서버 보안 설정을 갖추세요.

## 아키텍처와 사용 스택

| 영역 | 구현 |
|---|---|
| 화면 | `index.html`, `css/bundle.css`, `css/auth.css` |
| 관제·감지 UI | `js/bundle.js`, `js/events.js` |
| 계정 UI | `js/auth.js` |
| 감지 모델 | TensorFlow.js 4.22.0, COCO-SSD 2.2.3 (브라우저에서 CDN 로드) |
| 웹 서버·API | Node.js, Express 4 |
| 데이터베이스 | Node.js `node:sqlite`의 SQLite |
| 장치 연동 예제 | `arduino/mlx90640_thermal_beachwatch.ino` |

서버는 정적 화면과 `/api/auth/*` 등 API를 한 포트에서 제공합니다. SQLite 파일은 기본적으로 `data/beachwatch.db`이며 `BW_DB` 환경 변수로 경로를 바꿀 수 있습니다. `.env`, 데이터베이스 파일은 저장소에 커밋하지 않습니다.

## 기능 범위와 한계

- 사람 탐지는 COCO-SSD의 객체 탐지 결과를 사용합니다. 익수, 의식 상태, 실제 구조 필요성을 판정하는 모델은 아닙니다.
- 조명, 거리, 가림, 카메라 각도, 수면 반사와 장면 복잡도에 따라 오탐·미탐이 발생할 수 있습니다. 실제 운영 전 현장 조건으로 검증해야 합니다.
- 문자·이메일 발송이나 외부 알림 릴레이는 이 저장소의 현재 구현으로 확인되지 않아 제공 기능으로 안내하지 않습니다. 등록 연락처 관련 기능은 화면의 실제 동작을 확인하고 사용하세요.
- 첫 접속 때 CDN에서 라이브러리와 모델을 받아오므로, 사전 다운로드·캐시 상태가 확인되지 않은 오프라인 동작을 보장하지 않습니다.
- `server.js`는 단일 프로세스의 로컬 SQLite 구성을 사용합니다. 공용 인터넷 서비스에 바로 배포하기 위한 완성형 운영 구성이 아닙니다.
- 열화상 아두이노 스케치는 별도 센서·보드 연결이 필요한 예제입니다.

## AI 사용 내역

제품의 사람 탐지는 TensorFlow.js로 COCO-SSD 모델을 브라우저에서 실행합니다. 이 저장소의 구현은 감지 결과와 설정된 경계 기하를 사용해 위험 구역 진입 여부를 판정합니다. 외부 생성형 AI API를 호출하는 코드는 확인되지 않았습니다.
