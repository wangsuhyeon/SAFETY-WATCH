# Beach Watch

브라우저에서 카메라 영상을 분석해 설정한 경계선이나 위험 영역에 사람이 들어오는 상황을 감지하는 수변 안전 관제 프로토타입입니다. 감지 결과는 화면 경보(경보음·음성 안내·토스트)와 등록한 수신자에게 보내는 이메일·웹훅으로 표시합니다. 이 도구는 보조 경보일 뿐이며, 실제 구조·구난 판단은 대신하지 않습니다.

한국어·영어·중국어 UI를 제공하며, 카메라 입력은 최대 5대까지 구성할 수 있습니다. 영상 분석에는 브라우저의 TensorFlow.js와 COCO-SSD 모델을 사용하고, 계정 기능은 Node.js 서버와 SQLite 데이터베이스로 처리합니다.

## 문제 정의와 처리 흐름

관제자가 여러 카메라를 계속 살피기 어려운 상황에서, 설정한 위험 경계에 사람이 진입했음을 더 빨리 알아차리도록 돕는 것이 이 프로젝트의 범위입니다. 익수 여부와 구조 필요성을 직접 판정하지 않으며, 구조요원을 대체하지 않습니다.

```text
카메라 영상 → 브라우저의 TensorFlow.js / COCO-SSD → 경계선·영역 판정 → 화면 경보 · 수신자 알림
브라우저 계정 화면 → Express API → SQLite (계정·세션·이벤트)
```

## 주요 기능

- **설치 장소 유형**: 해수욕장, 강·계곡, 호수·저수지, 수영장, 드론 중 하나를 고르면 감지 민감도와 긴급 승격 시간이 장소별 기본값으로 바뀝니다. 선택한 유형에 따라 제목과 안내 문구도 함께 바뀝니다.
- **카메라 입력 5종**: 기기 카메라(USB 웹캠·내장 카메라·가상 카메라), 스트림 URL(HLS·MP4/WebM·MJPEG), 유튜브 주소 또는 화면 공유, 영상 파일, 시뮬레이션. 카메라가 없어도 시뮬레이션으로 감지와 경보 흐름을 확인할 수 있습니다.
- **경계 구역 편집**: 직선인 **경계선**과 닫힌 도형인 **위험 영역** 두 가지를 영상 위에 직접 그립니다. 점을 추가·드래그하고, 점을 두 번 클릭(터치는 두 번 탭)하면 그 점이 삭제됩니다. 점 줄이기, 높이·회전 조절도 가능하며, 같은 구역을 쓰는 카메라에는 한 번에 적용할 수 있습니다.
- **감지 튜닝**: 신뢰도 임계값, 확인 프레임 수, 긴급 승격 시간을 슬라이더로 조정하고, 주간·흐림·야간·혼잡 상황 프리셋(또는 자동 판별)을 고를 수 있습니다. 감시 시간대를 지정하면 그 시간대에만 경보를 울립니다.
- **3단계 경보**: 사람이 경계에 들어오면 확인 단계인 **주의**로 시작해, 지속 시간에 따라 **경고**(경보음·알림)와 **긴급**(반복 사이렌)으로 올라갑니다.
- **알림 수신자**: 최대 12명까지 등록하며 사람마다 수신 시작 등급(경고 이상/긴급만)과 근무 여부를 정합니다. 수신자별 **경고 문구 템플릿**(`{camera}`, `{level}`, `{count}`, `{seconds}`), 웹훅 URL, 이메일 주소를 지정할 수 있습니다.
- **이메일 자동 발송**: 외부 무료 서비스 FormSubmit을 사용하므로 별도의 키나 서비스 계정이 필요 없습니다. 설정 화면에서 테스트 메일을 보낼 수 있습니다.
- **관제 도구**: 화면을 가득 채우는 관제 모드와 단축키, 시스템 진단(자체 진단·부하 테스트), 지연·FPS·경보 횟수 계측, 담당자 확인까지 걸린 시간을 보여 주는 북극성 지표, 경보 순간 스크린샷, 이벤트 CSV 내보내기를 제공합니다.
- **열화상 아두이노 연동**: Web Serial로 MLX90640 열화상 카메라를 연결해 실시간 온도를 보고, 생체 열원(사람) 여부를 판정해 일반 카메라 감지 결과와 교차 검증합니다. 일반 카메라 화면에 열화상 시야를 맞추는 정렬 도구(가로·세로·시야 크기)와 온도 히트맵을 제공하며, 42°C를 넘는 뜨거운 물체는 사람으로 오인하지 않도록 제외합니다.
- **오프라인 준비와 개인정보**: 한 번 내려받으면 인터넷이 끊겨도 감지가 계속되고, 공용 PC를 쓸 때는 저장된 연락처·구역·설정을 한 번에 지울 수 있습니다.

## 빠른 시작

### 필요한 환경

- Node.js 22.13 이상 (`node:sqlite` 내장 API 사용)
- npm
- 카메라를 쓰려면 `localhost` 또는 HTTPS 주소로 페이지를 열어야 하며, 브라우저에서 카메라 권한을 허용해야 합니다
- 첫 모델 로드에는 인터넷 연결이 필요합니다. 라이브러리와 모델은 `index.html`에서 CDN으로 불러옵니다.

### 실행

프로젝트 폴더에서 실행합니다.

```bash
npm install
npm start
```

브라우저에서 <http://localhost:3000> 을 엽니다. 서버는 같은 주소에서 웹 화면과 `/api/*` 계정 API를 함께 제공합니다. 서버를 시작하면 `data/beachwatch.db`가 생성됩니다. 포트를 바꾸려면 `.env.example`을 참고해 `.env`에 `PORT=8080`처럼 지정하세요.

서버 상태는 <http://localhost:3000/api/health> 에서 확인할 수 있습니다.

### 운영 배포: 계정 기능 포함

`render.yaml`은 Render에서 이 저장소를 웹 서비스로 배포하기 위한 설정입니다. GitHub 저장소를 Render에 연결해 Blueprint로 배포하면 화면, Express API, SQLite가 같은 HTTPS 주소에서 동작하며 `/var/data` 영속 디스크에 데이터베이스가 저장됩니다. 배포가 완료된 서비스 주소로 접속하면 회원가입도 바로 사용할 수 있습니다.

기존 GitHub Pages·Netlify 같은 정적 홈페이지를 유지하려면 다음을 추가로 설정하세요.

1. `render.yaml`으로 API 서버를 배포하고, 서비스의 HTTPS 주소를 확인합니다.
2. API 서버 환경 변수 `APP_ORIGIN`에 정적 홈페이지의 정확한 주소를 등록합니다. 여러 주소는 쉼표로 구분합니다.
3. 정적 홈페이지의 `index.html`에서 `beach-watch-api-url` 메타 태그 `content` 값에 API 서버 주소를 넣고 다시 배포합니다.

이 구성은 CORS 허용 출처와 `SameSite=None; Secure` 세션 쿠키를 사용합니다. `APP_ORIGIN`에는 와일드카드를 쓰지 말고 실제 HTTPS 주소만 등록하세요.

## 첫 감시 설정

1. 오른쪽 카드에서 **설치 장소 유형**을 고릅니다. 장소에 맞는 감지 설정이 한 번에 적용됩니다.
2. **＋ 카메라 추가** 또는 **카메라 연결**을 눌러 기기 카메라, 스트림 주소, 화면 공유, 영상 파일, 시뮬레이션 중 하나를 선택합니다.
3. 카메라 화면이 선택된 상태에서 **그리기 시작**을 누른 뒤 영상 위를 눌러 경계 점을 추가합니다. 점을 끌어 위치를 바꾸고, 점을 두 번 클릭하면 그 점이 삭제됩니다. 점 줄이기와 높이·회전 슬라이더로 모양을 다듬고, 편집을 마치면 그리기 버튼을 다시 눌러 끝냅니다.
4. **경계선**은 선 바깥쪽(화면에서 안내하는 위쪽)에 들어온 사람을 감지하고, **위험 영역**은 닫힌 영역 안에 들어온 사람을 감지합니다. 그린 위치에서 방향이 맞는지 화면으로 확인하세요.
5. 여러 카메라가 같은 구역을 볼 때는 **모든 카메라에 적용**을 누릅니다. 카메라마다 다른 모양이 필요하면 카메라를 따로 선택해 각각 그리세요.
6. 경보를 받을 사람을 정하려면 **설정 → 알림 수신자**에서 이름과 이메일을 등록합니다. 등급과 발송 조건은 사람마다 다르게 지정할 수 있습니다.

카메라 영상은 브라우저 안에서만 분석되며 외부로 전송되지 않습니다. 브라우저 저장소에는 위험 구역과 화면 설정이 남을 수 있으므로, 공용 기기에서는 **설정 → 이 기기에 저장된 내 정보 지우기**를 사용하세요.

## 회원가입 및 서버 연결

회원가입·로그인·비밀번호 재설정은 `server.js`의 API와 SQLite가 실행 중이어야 작동합니다. GitHub Pages 같은 정적 호스팅에 파일만 올린 경우 계정 API가 없으므로 가입할 수 없습니다. `render.yaml`로 전체 앱을 배포하거나, 위의 분리 배포 설정으로 API를 연결하세요.

서버가 제공하는 API는 다음과 같습니다.

| 경로 | 기능 |
|---|---|
| `POST /api/auth/signup`, `/api/auth/login`, `/api/auth/logout` | 가입 · 로그인 · 로그아웃 |
| `GET /api/auth/me` | 현재 세션 확인 |
| `POST /api/auth/password/change` | 비밀번호 변경 |
| `POST /api/auth/reset/question`, `/api/auth/reset/verify` | 보안 질문으로 비밀번호 재설정 |
| `GET /api/events`, `POST /api/events` | 경보·감지 이벤트 저장과 조회 |
| `POST /api/events/clear`, `GET /api/users`, `GET /api/logs`, `GET /api/stats` | 관리자 전용 기록 조회와 통계 |
| `GET /api/health` | 서버 상태 |

로컬에서 "서버 응답을 받지 못했습니다"라는 메시지가 나오면:

1. 프로젝트 폴더에서 `npm start`를 실행합니다.
2. 터미널에 `Beach Watch server → http://localhost:3000`이 표시되는지 확인합니다.
3. `http://localhost:3000/api/health`를 열어 JSON 응답을 확인하고, 페이지도 `http://localhost:3000`에서 엽니다.
4. 정적 미리보기 서버나 `file://` 주소에서 열었다면 위 주소로 다시 접속합니다.

계정 비밀번호와 보안 질문 답변은 서버에서 해시해 저장하며, 브라우저에는 HttpOnly 세션 쿠키를 발급합니다. 로그인은 연속 5회 실패하면 15분간 잠기고, IP별 로그인 시도 횟수도 제한됩니다. 첫 번째로 가입한 계정은 자동으로 관리자 역할을 받습니다. 운영 환경에 공개하기 전에는 HTTPS, 백업, 데이터 보관 정책, 운영 서버 보안 설정을 갖추세요.

| 영역 | 구현 |

## 기능 범위와 한계

- 사람 탐지는 COCO-SSD의 객체 탐지 결과를 사용합니다. 익수, 의식 상태, 실제 구조 필요성을 판정하는 모델은 아닙니다.
- 조명, 거리, 가림, 카메라 각도, 수면 반사와 장면 복잡도에 따라 오탐·미탐이 발생할 수 있습니다. 실제 운영 전 현장 조건으로 검증해야 합니다.
- 이메일 발송은 외부 무료 서비스 FormSubmit을 사용합니다. 수신자 주소로 처음 한 번 확인(활성화) 메일이 갈 수 있고, 발송 성공 여부는 화면의 진단 로그로만 확인됩니다. 발송량 제한과 서비스 정책은 FormSubmit 쪽 조건을 따릅니다.
- 웹훅은 수신자에게 등록한 주소로 JSON을 POST할 뿐, 받는 쪽의 처리 결과는 확인하지 않습니다. 등록한 주소와 수신 서버의 동작을 직접 검증하세요.
- 문자(SMS) 발송 기능은 없습니다. 경보 토스트의 전화·문자 버튼은 기기의 전화 앱에 연결되는 링크일 뿐 자동 발송이 아닙니다.
- 「설정 → 인터넷 없이 쓸 수 있게 준비」를 실행하기 전에는 라이브러리와 모델을 매번 CDN에서 받아오므로, 오프라인에서 감지가 동작할 보장이 없습니다.
- `server.js`는 단일 프로세스의 로컬 SQLite 구성을 사용합니다. 그대로 공용 인터넷 서비스에 배포하기 위한 완성형 운영 구성은 아닙니다.
- 열화상 아두이노 스케치는 별도의 센서·보드 연결이 필요한 예제입니다.

## AI 사용 내역

제품의 사람 탐지는 TensorFlow.js로 COCO-SSD 모델을 브라우저에서 실행합니다. 이 저장소의 구현은 감지 결과와 설정된 경계 기하를 사용해 위험 구역 진입 여부를 판정합니다. 외부 생성형 AI API를 호출하는 코드는 없습니다.

문서 정리에는 AI 보조 도구를 사용해 코드와 README를 대조했고, 기능·환경 설명은 저장소의 소스·설정 파일과 API 점검 결과로 확인했습니다. 모델 학습, 자체 학습 데이터셋, 공식 성능 수치는 이 저장소에 포함되어 있지 않아 언급하지 않습니다.

```bash
npm test          # API 점검
npm run test:e2e  # 계정 브라우저 흐름 (Chrome/Chromium 필요)
npm run test:race # 동시 회원가입 점검
npm run test:email # 이메일 관련 UI/API 흐름
```
